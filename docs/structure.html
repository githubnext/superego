Superego: structure

A framework for agent apps. One daemon per machine, its own protocol, an Electron app layer, and extensions with a daemon half and a UI half. Apps are made with superego new. As of the icon work, 33 commits.

1 · Processes

Agents live in the daemon; every window and command is a client. Each app has its own daemon, data dir and command.

2 · Layers

Daemon halves go in src/daemon.ts, UI halves in src/renderer/main.tsx. Apps import extensions and the framework; extensions import the framework only. Arrows point at dependencies.

4 · Extensions

A package with ./daemon and/or ./ui, imported at build time. The daemon half announces ext:<name>, so the UI knows which machines have it.

threads · ui

The thread sidebar. Its ··· menu and settings: sort (newest, needs you first, recently active), a list or a rail (⌘\), and a details pane in thread.aside (⌘I). Without it, the shell shows a top-bar picker.

ask-user · daemon + ui

An ask_user tool that waits. The thread shows as needing you; the question sits in the composer, which it claims, so you answer by picking an option or typing.

5 · Protocol

JSON-RPC 2.0, a line per message, any transport. hello checks the generation and announces features, identity and build. Watches send a snapshot, then changes.

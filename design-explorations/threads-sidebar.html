A’s rows (glyph, title, time) at 32px in D’s quiet frame. One small menu turns the sidebar into the other three modes, so there is one extension, not four layouts.

What it needs

A place to keep the choice: the UI half needs its own settings (a sort and a view per window or app). Today only daemon halves can register settings.

Default when

Always, as the shipped default: least surprising, stable order.

What works

Facts leave the header and the transcript. It is a second extension slot (a pane beside the session), so git or diff panes can use it next.

What it needs

A session.aside slot in the shell, and data: model and cost exist in the daemon but aren’t sent to clients; files touched can be derived from tool calls.

Default when

You’re reviewing what a session did, rather than talking to it.

What this asks of the API

Everything above is one extension plus three small core additions.

UI settings →UI halves register app-scope settings (sort, show as), so the menu’s choice persists.
session.aside slot →A pane beside the session for details, then git and diff.
Session facts →Model, cost and last activity on SessionInfo; files touched derived.
Command palette →Switch by name when the sidebar is a rail.

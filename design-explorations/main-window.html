What works

Clear hierarchy from one scale (11.5 mono · 13 · 15 · 17) and an 8px rhythm with 24–28px between turns. The user turn as a left rule reads like a question in a document, not a chat bubble far right.

What risks

Long tool-heavy runs become a stack of grey lines; you need to click to see output. 15px body makes the sidebar (13px) feel like a different app unless both scale together.

Pick this if

You mostly read and steer one session at a time and want Superego to feel calm, like a document you’re working in.

B

Dense log

Optimizes for seeing a lot at once: a 4px grid, 12.5px base, a mono gutter with times, tool calls as rows with status, exit codes and durations. · Tradeoff warmth and reading comfort; it looks like a tool, and long prose answers are tiring at 12.5px.

What works

Every line earns its place: times, durations, exit codes and shortcuts are visible without opening anything. The inverted selected row and the one-line breadcrumb header make position obvious.

What risks

Mono everywhere tips into the “terminal cosplay” look. Needs real timestamps and durations, which sessions don’t expose yet (see manifest).

Pick this if

You run many sessions and machines and scan them like logs; the agent’s tool work matters as much as its prose.

C

Status-grouped workspace

Optimizes for triage across machines: the sidebar sorts by what needs you, and a right inspector holds the session’s facts, tools and files. · Tradeoff horizontal room; three columns need a wide window, and grouping by status moves sessions around as they change.

What works

Needs-you sits on top whatever the machine; the transcript stays uncluttered because facts moved to the inspector. It is also the first real use of a panel layout, which the framework needs anyway.

What risks

Sessions jumping between groups can disorient. The inspector shows data we don’t surface yet (model, cost, files touched), so it starts thin. Avatars add chat chrome a monochrome UI doesn’t need.

Pick this if

You want the window to answer “what needs me?” first, and you plan to build panels (git, diff, files) next.

D

Focus

Optimizes for one session at a time: the sidebar shrinks to a rail of status glyphs, a 26px title, 15.5/1.7 prose, and a floating composer that holds the question. · Tradeoff navigation and context. Titles hide behind the rail (⌘K to switch), and tool steps compress to a line.

What works

The most generous type and whitespace of the four; the question and the reply live in one floating card, so what the agent needs is always in reach.

What risks

Without titles in view, switching depends on a command palette Superego doesn’t have yet. The floating dock covers content on short windows.

Pick this if

Superego is mostly launched per project with superego, and you want each window to be about the one thing it was opened for.

How to pick a direction

The pick’s type scale and spacing become tokens in @superego/ui; its layout becomes the shell’s default.

Calm reading →A. Document
Many sessions, logs →B. Dense log
Triage, panels next →C. Workspace
One thing per window →D. Focus
